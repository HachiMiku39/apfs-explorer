# Upstream reuse assessment — 2026-11-05

Decision: fork APFS Explorer; keep its Rust engine, WinFsp integration, Tauri GUI, Unicode logic, caches and test harnesses. Do not rewrite reliable components. Separate upstream claims from reproduced evidence.

| Project | Code/features and tests inspected | License / reuse decision |
|---|---|---|
| [enesilhaydin/apfs-explorer](https://github.com/enesilhaydin/apfs-explorer/tree/7d6cd8006e9234f9d4aabe9d132cb89227ecd6d3) | Rust workspace: apfs-core/apfs/apfs-write/winfsp-host/Tauri. COW transactions, flush barriers, snapshots, file ops and fault devices already exist. Many integration tests return early without fixtures/environment gates. Original CI only tested library units on Linux/macOS and built Windows host; it did not qualify Explorer, physical 4TB media or Windows 10. Read-only image path and snapshot list opened RW; one-shot and raw writes accessible. | GPL-3.0-only; best fork base. Close shipping write paths and use genuinely read-only handles. |
| [libyal/libfsapfs](https://github.com/libyal/libfsapfs) | C library; experimental read-only APFS v2; encryption, decmpfs, xattrs. tests and ossfuzz directories. README excludes v1, Fusion, snapshots, T2 encryption and some compression methods. No write engine to reuse. | Library LGPL-3.0-or-later, tools under GPL terms; potential independent differential reader, not introduced as a v0.1 dependency. |
| [ErsinZorba/APFS-For-Windows](https://github.com/ErsinZorba/APFS-For-Windows) | C#/.NET WinFsp service/tray/core, 10 UI languages, read-only OS handles, per-disk write gate, image builder and independent 7-Zip/Linux/macOS harnesses. README claims encryption and experimental writes, with substantial exclusions. Claims are not independently reproduced here. | GPL-3.0-only. Architecture/test reference; replacing Rust/Tauri would add integration cost. No code imported. |
| [winfsp/winfsp](https://github.com/winfsp/winfsp) | Existing signed driver + user-mode API, native/FUSE/.NET bindings, x64/ARM64, test framework and NTFS compatibility documentation. Supplies no APFS parser. | GPLv3 + FLOSS exception (commercial option also exists). Reuse via existing Rust binding; retain official runtime distribution and notices. |
| [linux-apfs/linux-apfs-rw](https://github.com/linux-apfs/linux-apfs-rw) | Linux C kernel module, experimental writes, default read-only. README warns corruption risk, no encryption and limitations on Fusion writes. Useful transaction/allocator reference and independent apfsprogs tools; cannot directly become a Windows user-mode Rust driver. | [transaction.c](https://github.com/linux-apfs/linux-apfs-rw/blob/master/transaction.c) explicitly uses `GPL-2.0-only`; the baseline NOTICE incorrectly calls the project GPL-2.0+. Do not copy that implementation into GPL-3.0-only code. No new code imported; inherited reference provenance still needs a file-level audit. |

Sources: repository READMEs, LICENSE/COPYING/NOTICE, manifests, source modules, tests and workflows at inspection time. Exact source for the chosen base is pinned above. Other upstreams remain moving references and must be pinned before adding a dependency or oracle.

Known upstream issues include [Windows 10 validation #19](https://github.com/enesilhaydin/apfs-explorer/issues/19), [hard link/range clone APIs #22](https://github.com/enesilhaydin/apfs-explorer/issues/22), and [read cache #17](https://github.com/enesilhaydin/apfs-explorer/issues/17). Hard-link creation is limited by WinFsp, not solved by exposing the library writer.

No numeric line/branch coverage report was available in the inspected baseline; test counts and upstream “audit-verified” wording are not coverage measurements or independent safety certification. The inherited NOTICE mentions references but is not a file-level provenance audit. cargo-deny adds a dependency SPDX gate; retain the original notices and verify any future copied code separately. GPL-2.0-only code must not be combined into a GPL-3.0-only derivative without compatible permission.
